原文
I was looking through some recent llama.cpp CUDA work and this thing came up that they're experimenting with CUTLASS-based MoE prefill kernels on Blackwell (SM120) for MXFP4 and NVFP4. Source if you guys want to explore github.com/duanyytop/agents-radar/issues/2586 FP4 is no just a speedup. It's a smaller payload. That's easy to miss if you only look at llama.cpp from the outside. People see MXFP4 and NVFP4 land for local MoE models and assume the win is automatic 16-bit to 4-bit less VRAM faster prefill bigger model on a 5090 or a PRO 6000. The format helps. The kernel is what decides a llama.cpp CUDA path still has to pay for all of this load scale / dequant GEMM routing epilogue Lower precision only shrinks one of those. On MoE it gets noisier. Tokens get routed to experts, packed, multiplied against different expert weights, then merged back. That's the difference between running gpt-oss, Qwen3 MoE, or Gemma MoE locally and just "having a 4-bit file." This is why the recent CUDA work matters. Not because FP4 is fashionable, but because prefill on Blackwell only gets faster if the scales, layout, Tensor Core instructions, accumulation, and expert grouping all move cleanly. Otherwise you get a smaller model that still stalls in routing and dequant. The datatype tells you how the weights are stored. The kernel tells you whether that storage becomes tokens per second. So the useful question for llama.cpp is can the whole local inference path make FP4 worth it on a real MoE workload? That's the job. Not just fitting the model on one GPU Making the representation the memory traffic the instructions and the hardware agree.日本語訳最近の llama.cpp の CUDA 周りを追っていたら、Blackwell（SM120）向けに MXFP4/NVFP4 の CUTLASS ベース MoE prefill カーネルを実験しているのが目に入った。FP4 は単なる高速化ではなく「小さいペイロード」だ。外から llama.cpp を見ているだけだと見落としやすい——16bit→4bit で VRAM が減り prefill が速くなり大きいモデルが 5090 や PRO 6000 に載る、と自動的な勝利だと思ってしまう。だがフォーマットは助けにすぎず、決めるのはカーネルだ。CUDA パスは結局 load／scale・dequant／GEMM／routing／epilogue の全部にコストを払う。低精度はそのうち 1 つを縮めるだけ。MoE ではさらに厄介で、トークンはエキスパートにルーティングされ、パックされ、異なるエキスパート重みと掛け合わされ、また統合される。これが gpt-oss・Qwen3 MoE・Gemma MoE を「ローカルで動かす」ことと「4bit ファイルを持っているだけ」の違いだ。最近の CUDA 作業が効くのは FP4 が流行だからではなく、scale・レイアウト・Tensor Core 命令・accumulation・エキスパートのグルーピングが全部きれいに動いて初めて Blackwell の prefill が速くなるから。データ型は重みの格納方法を語り、カーネルはその格納が tok/s になるかを語る。だから有用な問いは「ローカル推論パス全体が、実際の MoE ワークロードで FP4 を割に合わせられるか」だ。それが仕事であって、モデルを 1 枚の GPU に載せることではない。
